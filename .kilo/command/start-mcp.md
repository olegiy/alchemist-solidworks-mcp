description: Проверить и запустить MCP-сервер SOLIDWORKS этого проекта
---

Подготовь и запусти MCP-сервер Alchemist для SOLIDWORKS в текущем репозитории.
Выполни необходимые действия сам, а не выдавай пользователю инструкцию по установке.
Соблюдай AGENTS.md и разрешения текущего клиента. Не создавай CAD-документы.

## Порядок действий

1. Если инструмент `ensure_ready` именно этого сервера уже доступен, вызови его
   без параметров. При ответе `ready: true` задача завершена: ничего не переустанавливай.
   Не подменяй его инструментом другого сервера SolidWorks.

2. Если сервер не подключён или вызов завершился ошибкой, проверь установку.
   Корень проекта обозначен далее как `<ROOT>`. Команды выполняй из этого корня.
   Нужны Windows, Python 3.11+, SOLIDWORKS и .NET Framework 4.8.
   Проверь наличие `.venv/Scripts/python.exe` и
   `execution/solidworks/SolidworksExecution/bin/Debug/SolidworksExecution.exe`.
   Если Python из `.venv` доступен, запусти диагностику:

   ```powershell
   & .\.venv\Scripts\python.exe .\tools\doctor.py
   ```

   Отсутствие Simulation или регистрации в Claude Desktop не мешает обычному CAD
   через Kilo. Исправляй только проблемы, относящиеся к запуску текущего сервера.

3. Только если отсутствуют зависимости или execution-сервер, либо нужна пересборка,
   выполни установку:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -NoRegister
   ```

   Установщик останавливает `SolidworksExecution` и устанавливает Claude skills.
   Если execution-процесс уже работает, сначала получи разрешение на его остановку;
   не прерывай текущую CAD-операцию. Сохрани существующий режим SOLIDWORKS:
   при повторной установке общего экземпляра добавь `-SharedInstance`.
   Не удаляй `own_instance.flag` в проекте или `%USERPROFILE%/SolidWorksMCP`.
   При нестандартной установке SOLIDWORKS уточни путь по установленным файлам,
   передай `-SwApiDir "<SOLIDWORKS>/api/redist"` и задай `SWMCP_SW_EXE` для скрытого
   экземпляра. Если нужного ПО нет, сообщи, какой именно компонент требуется;
   не устанавливай SOLIDWORKS и не меняй системные права самостоятельно.

4. Проверь конфигурацию MCP-клиента. Для Kilo используй существующий проектный
   `kilo.json` или `kilo.jsonc`; проверь также конфигурацию в `.kilo`.
   Если проектной конфигурации нет, создай `.kilo/kilo.json`.
   Добавь или исправь только запись этого сервера, сохранив остальные настройки.
   Не создавай дубликат уже работающей записи. Образец:

   ```json
   {
     "mcp": {
       "solidworks-alchemist": {
         "type": "local",
         "command": [
           "<ROOT>/.venv/Scripts/python.exe",
           "<ROOT>/adapters/claude/server.py"
         ],
         "environment": {
           "PYTHONIOENCODING": "utf-8",
           "PYTHONUTF8": "1"
         },
         "enabled": true,
         "timeout": 180000
       }
     }
   }
   ```

   Замени `<ROOT>` реальным абсолютным путём; в JSON используй прямые слеши.
   Образец является фрагментом для слияния, не заменой всей конфигурации.
   Для другого MCP-клиента используй его формат подключения через `stdio`,
   сохранив те же Python, скрипт и переменные окружения.

5. Переподключи MCP штатным способом клиента, если он доступен агенту.
   Если требуется действие пользователя, сообщи только одно действие:
   «Перезапустите MCP-клиент, затем повторите /start-mcp».
   Не запускай `server.py` отдельно в фоне: его `stdio` должен принадлежать клиенту.
   Не запускай execution-сервер вручную: адаптер запускает его автоматически.

6. После подключения вызови `ensure_ready` без параметров и проверь `ready: true`.
   Только этот ответ подтверждает готовность всего стека. Наличие процесса,
   открытый порт или успешный `doctor.py` сами по себе готовность не подтверждают.

## Ограничения

- `http://localhost:8778` является внутренним HTTP API, не MCP-адресом.
  Не настраивай подключение MCP по этому URL и не заменяй `localhost` на `127.0.0.1`.
- Не меняй исходный код сервера, чужие MCP-записи, разрешения и глобальные настройки.
  Не выполняй `git pull` и не создавай новые сессии или worktree.
- Не завершай процессы принудительно и не закрывай диалоги SOLIDWORKS автоматически.
  `ensure_ready(close_dialogs=True)` может отменить операцию и требует согласования.
- Если получен `running: true` с `job_id`, получай результат через `job_result`;
  не повторяй исходную операцию.
- При ошибке используй `adapters/claude/adapter.log` и
  `execution/solidworks/SolidworksExecution/bin/Debug/execution.log`.
  Не выводи секреты из конфигурации или окружения.

## Ответ пользователю

Не более трёх коротких строк: готов ли MCP, подключён ли SOLIDWORKS, чем это проверено.
Если запуск заблокирован, вместо заявления об успехе назови причину и одно необходимое
действие пользователя. Не утверждай, что сервер запущен, пока нет `ready: true`.

# Статус стенда

Стенд находится в разработке. `scenarios.json` — спецификация, не исполняемый CAD-сценарий.
`cad_oracle.py` оценивает переданные наблюдения, но пока не собирает независимые CAD-доказательства.
Отсутствие наблюдения возвращает `unknown`; `verified` старого API не доказывает качество.

Безопасный просмотр корпуса:

```powershell
.venv\Scripts\python.exe tools\bench_cad.py
```

Анализ парных времён из JSON `{"a": [10, 11], "b": [9, 10]}`:

```powershell
.venv\Scripts\python.exe tools\bench_cad.py --results D:\Bench\paired.json --seed 42
```

Анализатор не объявляет ускорение: bootstrap CI без независимого качества,
предрегистрации, проверки p95 и множественных сравнений недостаточен для приёмки.
`holm` и `paired_schedule` — отдельные функции, ещё не полный acceptance pipeline.
`--live` отклоняется до реализации ownership и независимых probes.

Низкоуровневый Python API `replay_stdio(..., live=True)` подключён к MCP SDK,
но не является готовым live-стендом: не обеспечивает ownership, завершение jobs
или независимый audit. Не использовать его для пользовательских документов.
Transport/session lifecycle проверен fake-тестами, реальный stdio запуск не проверен.

## Недостающие независимые probes

- Существующие mass/face reads могут дать геометрические наблюдения, но их
  округлённый MCP-вывод нельзя автоматически считать достаточным для допуска 0,01%.
- `GetSystemValue3` должен возвращать raw actual; ошибка чтения не допускает fallback
  к requested-value. Доказательство измерения привязывается к документу/configuration.
- Sketch constrained status недостаточен сам по себе: нужны semantic role/type
  relations и participation в driving dependency, без привязки к локализованным именам.
- Аудит +10% требует отдельной копии результата и проверки обеих фаз изменения/возврата;
  создание копии, безопасный выбор документа и ownership ещё не реализованы.
- До реализации этих probes `audit_scenario` не выдаёт `passed` для всего задания,
  даже если все переданные значения совпали.

## Протокол будущей live-серии

1. Зафиксировать commit A/B и исходный baseline, SW/interop, видимость, конфигурацию,
   хост/нагрузку, идентификатор корпуса, основной показатель, размер серии, seed,
   budget 600 s и лимит трёх исправлений до запуска серии.
2. Создать отдельный output-root и реестр только принадлежащих стенду документов.
   Не закрывать пользовательские документы, не применять `close_all` и не завершать
   пользовательские процессы. Каждую пару начинать с независимых свежих документов.
3. Детерминированный replay проводить через реальный MCP stdio; `run_mcp.py`
   остаётся in-process и не измеряет транспорт. Отдельно учитывать cold/warm.
4. При `running` получать результат существующего job, не повторять CAD-операцию.
   Текущий offline replay вместо этого безопасно останавливается с `unknown`.
   Timeout не отменяет COM: дождаться известного завершения до cleanup/reset.
5. После timed workflow собирать независимый audit, отдельно учитывать `T_audit`.
   Проверять размер, поверхности и отверстия, rebuild, sketch relations и driving
   dimensions. Bbox и объём сами по себе недостаточны.
6. На отдельной копии результата проверить ведущий размер +10%, зависимости и
   восстановление исходного значения с повторным измерением. Не подменять actual
   requested-value. Недоступный probe исключает приёмку, а не критерий.
7. Начать с 12 exploratory пар; подтверждающая новая серия — минимум 30 balanced
   AB/BA пар. Bootstrap — 10000 seeded samples медианы парных log(B/A); Holm для
   нескольких сценариев. p95 до 100 наблюдений на вариант/страту описательный.
8. Сохранить все попытки и исходы, включая timeout/unknown/failure; публиковать
   стоимость правильного результата по времени всех попыток. Не исключать failures
   из временной выборки. Ноль правильных результатов означает unavailable.
9. Приёмка требует CI ниже 1, отсутствия потери passed-критериев, false acceptance,
   неизвестных исходов, поздних изменений и p95-регрессии. Иначе `no evidence` либо
   `quality regression`, без заявления об ускорении.

## Rollback текущего кандидата

C# `Infrastructure/PerfTrace.cs` пока не подключён к production calls. Pure harness
`tools/bench/PerfTraceHarness.cs` компилируется отдельно с этим файлом под net48,
не требует interop и не запускает COM. Он проверяет clock, disabled/allowlist,
изоляцию sink errors и однократный Dispose; это не live-проверка SOLIDWORKS.

Tracing выключен без `SWMCP_PERF=1`. Для удаления integration вернуть только
добавленные `span` вокруг `call_tool` в `adapters/claude/session.py`, сохранив
исходный порядок UUID/state-version/resync. Остальные новые файлы не включены
в production workflow. Не откатывать или повторять CAD-операции в текущем документе.
